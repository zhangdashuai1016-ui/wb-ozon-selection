## 1. 这一轮解决什么

### 1.1 三件事，各自独立

| 编号 | 事 | 性质 |
|---|---|---|
| ⑥ | **续写之后一旦失败，失败本身落不了盘** | 从未飞过的路上的真缺口 |
| ⑤④ | 主人自己在后台填了库存，软件要**诚实地登记**而不是谎报自己写过 | 主人 2026-09-24 决定 |
| ⑦ | Ozon 后台报的「#主题标签」格式错误 | 主人指定要修 |

### 1.2 ⑥ 的根因：两处租约，只同步了一处

库存续写会**重新领取、铸出新租约**（`lease:d-inventory:*`），而准备证据记的是导入那次的租约（`lease:de:*`）。前缀由构造决定，**永不相等**。

- `d-e-software-job-results.mjs:148` 比 `state.softwareJobRef` —— `resumeDRemainingInventoryInDocument:204` **同步了**；
- `d-production-preparation-contract.mjs:66` 比 `preparationEvidence` 的持有者 —— **没同步**。

分界在 `results.mjs:160`：第 187 行那道断言在 `if (state.status !== "succeeded")` 块里。
**成功档根本走不到**（所以 CI 一直绿、链也能跑通），**失败／unknown 档必炸，而且炸在结算事务里**。

### 1.3 ⑥ 的后果：半套写入 + 无法判断卡点

事务回滚，软件**没法把这次失败记成失败**。实测落盘：

```
D作业 : waiting_platform / in_flight / failureClass null   ← 没有失败分类
执行  : in_flight，attempt.failure null，attempt.reason null
platformWrites : unknown                                  ← 可库存其实已经写进去了
生产记录 : null      观察作业 : 3 条全 completed（泵不会再跑）
真实原因（回读价 99 ≠ 授权价 63.85）: 落盘里找不到
```

对照 AGENTS 第 0 节「已知失败必须由软件分类、持久化并安全停止」「不得导致状态丢失、**半套写入**或**无法判断卡点**」——同时踩中后两条。**形状与背心本次原始事故一致：作业卡住、查不出为什么。**

### 1.4 ⑦ 的根因：我们把字段的名字认错了

```
lib/platform-write-bindings.mjs:10
  { title: 4180, description: 4191, searchKeywords: 23171 }
```

**23171 在 Ozon 是 Хештеги（主题标签），不是自由搜索词框。** 证据就在仓库里：
`tests/c1-product-plan.test.mjs:1199` 那个类目属性的 label 写着 **`"#Хештеги"`**，`#` 就在标签里。

名字错了，值的形状自然就错。`ozon-seller-api-production-adapter.mjs`（原文）把所有词用空格拼成**一条**发给它：

```
хаки Оксфорд Для кошек      ← 一条、没有 #、内部全是空格
```

Ozon 规则：每个标签以 `#` 开头、标签之间用空格分隔、**标签内部不能有空格**。两条同时违反。
内容评级 59.5（特征 7.5/30、媒体 27/45），后台报「#主题标签」格式错误。

## 3. 爆炸半径

### 3.1 ⑦ 会让**已经冻结的 D 执行请求**失效

机制是死的（`lib/platform-write-preflight.mjs:65`）：

```js
const importRequest = buildOzonSellerImportRequest(projectProductionPlanImportPayload({productionPlan, …}));
if (!isDeepStrictEqual(request.productImport, importRequest)) throw new Error("D_EXECUTION_AUTHORIZATION_SCOPE_MISMATCH: 导入字段不属于冻结计划");
```

左边是**授权时冻结**的（旧格式），右边是**现在重建**的（新格式），必然不等。

**实测血量（正式数据副本，只读统计）：**

```
候选总数 62 ｜ 有生产授权的 2 ｜ 有已冻结 D 执行请求的 1 ｜ 有已保存 productionPlan 的 1
```

**那 1 个就是背心自己，而它走登记档、不重发导入。实际影响为零。**
另一个有授权的候选尚未冻结 D 请求，其计划会用新格式现建，不受影响。

**本轮决定：不做兼容**（讲解会话 2026-09-24 定）。理由：影响面 1 个且不走那条路；为一个不会发生的场景加兼容分支，等于把旧的错误格式永久留在代码里。

### 3.2 冻结请求前置校验

为避免给主人留一条**注定失败**的路，`resumeInventory` 在发出任何请求之前先试重建一次冻结请求；重建不一致即停，失败码 `inventory_request_superseded`，**零外部请求**。
新授权的品其冻结请求是按当前代码现建的，此处必然通过，**软件写库存的正常路径不受影响**。

### 3.3 ① 与新门的运营后果：**今后每个新品上架前都要先配策略并重启服务**

观察策略按 **候选 + SKU + 生产绑定** 逐条匹配（`lib/runtime-configuration.mjs:44`），
没有店铺级默认值。配合 r69 那道严格门（没有可用策略就拒绝上架、零外部请求），后果是：

> **每上架一个新商品，都必须先在 LaunchAgent 的 `SELECTION_REVIEW_D_PLATFORM_OBSERVATION_JSON`
> 里为它加一条策略，然后重启服务，D 才会执行。**

这是主人 2026-09-23 选定严格档（A 方案）的**代价**，不是缺陷——它换来的是
「导入发出去了却没人跟进」这类事故不会再发生。主人有权随时砍掉这道门。

**下一个品要计时的话，这一步要算进去。**
减轻办法（店铺级默认策略，让新品不必逐个配）记入第 7 节下一轮待办。

## 4. 主人手填库存：为什么不生成 productionRecord

AGENTS 10.2：**ProductionRecord 必须绑定本轮真实执行回执。**
库存不是软件写的，就没有库存写入回执。照抄一个、或拿回读结果倒填一个，等于**把回读事实冒充成写入回执**——这正是 AGENTS 10.1 区分「本次创建成功 / 平台外部已有 / 结果未知」要防的事。

所以登记档止于登记：

- `platformWrites` 记 **1**（只有那一次导入）
- `inventoryWriteState` 保持 `not_sent`
- `productionRecord` 保持 **null**，**不排 E 作业**
- 登记记录落 `lifecycleV11.dOwnerStockRegistrationV1`，含 taskId、product_id、仓库号、授权值、回读值、`stockSource: owner_manual`、观察指纹、主人身份、时间
- 回执 payload 明写 `inventoryReceiptRef: null`、`productionRecordCreated: false`、`eReadbackQueued: false`

**E 由主人人工核对。**（背心本来也会因 CDN 图片映射停在 not_verified，需主人肉眼核图。）

## 7. 踩坑留痕（给下一个接手的人）

1. **排练时钟**：观察按 `intervalMs` 节流，排练要推时钟，于是 `settledAt` 会**晚于真实 now**；而终态读取要求 `observedAt >= settledAt`。视图第一次渲染报 `OWNER_STOCK_SOURCE_INVALID` 就是这么来的，**不是代码问题**。观察时刻取在结算之后即可。
2. **fixture 里凑出来的数值会让整组用例名不符实**：观察 fixture 原本让仓库在写入**之前**就返回 `free_stock: 100`（为了让写入后的回读对得上），可 100 正是授权锁定值。加入库存判定后，`d-remaining-inventory-admission` 7 条全红——不是新代码错，是那 7 条测的东西和名字写的不是一回事。已改为可配、**默认 0**（空仓才是软件写库存的前提）。
3. **`!== undefined` 守卫**：fixture 不造该字段，这道闸在测试里就等于不存在。见 5.3。
4. **预览与适配器各拼各的**：`ozon-final-product-preview.mjs` 原本自己 `.join(' ')` 拼标签值，和适配器两套代码。**主人在确认卡上看到的不保证等于实际发出的。**已合并为同一个 `ozonHashtagAttributeValue()`。
   （更正：我先前报告说「确认卡上仍是词、展示层要另做、进下一轮」——**说错了**，真实原因是两处各拼各的，已当轮修掉。）
5. **浏览器包不许被服务端模块污染**：为了让预览和适配器共用一份标签格式化，我一度让
   `lib/ozon-final-product-preview.mjs` 去 import 服务端适配器——而预览是要打进浏览器包的
   （`src/components/FinalProductPlanCard.jsx` 引它），于是 `node:crypto` 被拖进前端，
   **`vite build` 直接失败**。已抽出零 `node:` 依赖的 `lib/ozon-hashtag-attribute.mjs`，
   文件头钉了一行「这个模块不许依赖 node: 内置模块」。
   **要不是这一轮重编了前端，它会以「界面静默上不了线」的形式出现在主人那儿。**
6. **改了代码要同步改已发布 schema**：③ `stopTrigger` 上午只改了代码，没进
