r67 已于 2026-09-23 部署（回执 `部署生效回执-r67-2026-09-23.json`）。主人当天按卡操作后，商品**没有上架**，并且三个按钮全部熄灭。本卡修的就是这件事。

## 1. 这一轮解决什么

### 1.1 唯一根因

`lib/d-e-runtime-view.mjs` 里判断「本商品的 D 作业是否同源」时，比较的是**该候选的全部** D 作业。作废一轮授权之后，被归档那两轮仍留在作业表里（按规矩一条不删），它们带的是**旧**授权号，于是断言不成立，视图判 `DE_SAVED_JOB_REFERENCE_CONFLICT`。

### 1.2 后果比「按钮全灭」严重得多

「通过进入生产授权」这一下**会自动起跑**：授权提交成功后，路由立刻 `await ozonAccountReadServices.continueProduction(...)`。而 `continueProduction` 在建完视图后有一行回落：

```js
if (!view?.canContinueSaved) return deRuntimeServices.continueSavedCurrent(input);
```

它位于 `await evidenceSource.publish(...)` **之前**。所以视图一判来源冲突，就**跳过「把账户证据发布到当前授权键下」整段，直接裸跑** D 执行。前检必然报账户证据不完整，新授权的第一轮当场烧掉。

**这是 AGENTS 8.3 禁止的静默降级：软件自己换了路径，没有告诉任何人。**

### 1.3 主人当天的操作没有错

13:34 那次账户核验 `revision=74 / completed`，落在 `validOzonAccountReadRevisions` 算出的 `[75, 74]` 集合里，会被正常选中，有效期到 2027-01-13。**不需要重做账户核验。**
