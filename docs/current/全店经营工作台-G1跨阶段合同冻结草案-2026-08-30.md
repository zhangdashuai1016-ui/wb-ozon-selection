## 1. 本轮范围与固定产品边界

第一阶段只验收一件准确商品在准确平台、店铺、SKU和revision下完成：

1. A：选品与货源确认。
2. B：成本与利润核算。
3. C1：商品资料、合规与文案准备。
4. C2：图片素材与最终上架卡确认。
5. D：按精确授权正式上架。
6. E：独立回读核验。

F—I后置，不是本轮缺口或验收前提。小地图只读展示项目逻辑、进度、证据和断点，不保存业务真相、不执行动作，也不阻塞A→E。

## 3. 单一对象身份合同

稳定合同编号：`G1-ID`。

### 3.1 规范身份对象

后续共享Schema必须以一个明确的身份包表达以下字段；字段名可以在W7落Schema前按项目命名约定定稿，但语义不得改变：

| 身份 | 必填语义 | 禁止替代 |
|---|---|---|
| `candidateId` | 商品方向的稳定候选身份 | 标题、URL、数组位置 |
| `skuPackageId` | 当前平台＋店铺分支的SKU生命周期身份 | candidateId、supplierSkuId |
| `platform` | `ozon`或`wb`等目标平台 | 店铺显示名 |
| `storeRef` | 稳定店铺引用；内部`stableStoreId`是项目主键，平台`sellerId/storeId`是当前官方观察身份，两者必须有版本化映射 | 显示名称、默认店铺、相邻店铺 |
| `merchantSku` | 本店铺使用的商家货号 | supplierSkuId、platformProductId |
| `supplierSkuId` | 主人确认的供应商变体身份 | merchantSku、offerId |
| `warehouseRef` | D库存写入所使用的稳定仓库引用 | 默认仓、首个仓库 |
| `credentialAlias` | 不含秘密的凭据引用，且必须与storeRef一致 | Token、Cookie、完整Key |
| `platformProductId` | D回执或外部发现后取得的平台商品身份 | merchantSku、supplierSkuId |

`merchantSku`与`supplierSkuId`必须分开取得、保存、校验和展示；`merchantSku`绝不能由`supplierSkuId`默认推导。即使文字相同也只是两个字段碰巧同值，不能共用身份语义。

`credentialAlias`只作为授权、作业和执行的非秘密引用；它不得进入纯利润或商品事实计算，也不能单独证明权限有效。Worker能力必须按平台和stableStoreId限定，领取时重新核对当前registry、登录有效性和租约。

### 3.2 revision关系

- `sourceRevision`：动作开始时实际读取并冻结的候选revision。
- `resultRevision`：推进业务状态的原子提交成功后，由repository校验并产生下一revision；当前单步合同目标是`sourceRevision + 1`。幂等重复命中只返回既有结果及其原`resultRevision`，不得再次加一。非推进型作业状态和旧revision终态使用独立记录版本，保留原`sourceRevision`且不得改变当前candidate revision。
- 输入、作业、授权、执行意图、回执和E记录必须绑定candidate、skuPackage、platform、storeRef和revision。
- 当前revision变化后，旧revision作业不得领取、不得发出新外部请求、不得写入当前SKU。
- 已经发生的旧revision外部请求必须保存真实终态用于审计；旧终态只能进入历史证据，绝不能推进当前revision。
- 旧revision若请求可能已发出但终态不明，必须保持`unknown_outcome`并进入对账，不能通过创建新revision绕过。

### 3.3 当前实现状态

- `candidateId`、`skuPackageId`和部分revision门已有源码与测试证据。
- 稳定storeRef、credentialAlias、warehouseRef和独立merchantSku尚未形成已验收的共享合同，标记`待施工`。
- 当前D/E代码把merchantSku与supplierSkuId混用，标记`已验证冲突`。

### 4.2 工作台和小地图另行分开展示四类视图

1. 业务阶段/结果：商品走到哪里、业务判断是什么。

#### ProfitModel强制分型

- `formal`：全部必要证据正式有效，才允许`passed`或`rejected`，只有`formal + passed`可以创建C1交接。
- `conditional`：包含任何估算佣金或其他获准估算，只能保存条件测算和证据缺口。
- `incomplete`：必要输入缺失或无有效数值，不得形成利润通过/不通过。
- 估算佣金无论利润数字多高，永远不得B通过、不得创建C1、不得改变负责人到C1。

当前实现说明：估算佣金能够形成passed并创建C1，属于`已验证P0冲突`。

#### 不可变对象链

`ProductionAuthorization → ProductionPlan → ExecutionIntent → ProductionRecord`

- 后一对象只读取并绑定前一对象，不得重新推导A/B/C现场字段。
- 任何店铺、merchantSku、价格、库存、素材、范围或排除项变化都必须新建authorizationId和revision。
- 当前源码中的库存100是已验证的旧实现常量，不是G1合同默认。ProductionAuthorization必须锁定主人对当前SKU精确确认的实际库存；未确认即停止，D不得使用隐藏默认值覆盖。
- 外部请求前先保存intent，attempt固定1；平台明确失败才failed，请求可能发出但终态不明必须unknown_outcome。
- unknown_outcome只能先对账；原授权不得直接重放。
- D为了判断本次写请求是否形成可保存的ProductionRecord而进行的即时写后读取，只属于D终态收口证据；它不是独立E，不得生成EVerificationRecord或把E标记完成。

## 6. SoftwareJob与原子交接合同

稳定合同编号：`G1-JOB`。

### 6.1 创建和身份

每个正常作业必须绑定：jobId、jobType、candidateId、skuPackageId、sourceRevision、platform、storeRef、sideEffectScope、authorizationRef、credentialAlias或能力引用、requiredCapabilities、requestedBy、owner、idempotencyKey和输入指纹。纯计算作业的credentialAlias必须明确为不适用，不得伪造默认凭据。

创建作业和上游阶段结果/下游handoff intent必须在同一repository事务中提交；失败不得留下半套状态。

### 6.2 lease、attempt和幂等

- 只有当前registry中online且能力匹配的worker可以领取。
- 领取必须创建有上限的lease；workerId、leaseId和服务端时间必须一致。
- 外部路径`attempt=1`，不得自动重试、换模型、换数据源、换浏览器或唤醒Codex。
- 相同幂等键＋相同输入指纹返回原结果；同键不同输入、同revision不同副作用必须冲突停止。
- 幂等键和互斥范围必须由服务端按规范输入与sideEffectScope生成；不能信任调用方随意提供的字符串。同店铺、同merchantSku、同不可重复副作用在任何revision存在in_flight或unknown_outcome时，新revision也不得绕过互斥门。
- 单SKU动作只读取目标candidate/SKU/job和必要策略，不全量扫描决定业务。

### 6.3 重启、过期和unknown_outcome

- 未发送外部请求：重启或lease过期可明确收口为failed/not_sent。
- 已发送且平台明确失败：failed，并保存固定failureClass和安全evidenceRef。
- 已发送且终态无法证明：unknown_outcome，禁止自动重放。
- 平台明确处理中：waiting_platform，只允许合同预先定义且已经授权的有限对账/回读；不得重放或补发写请求。
- settle前必须重新核对当前candidate、skuPackage和revision。
- 旧revision终态可以追加到历史审计，但结果引用不得写入当前revision对象，不得触发handoff或阶段推进。

## 7. 错误、秘密与外部授权合同

- 错误必须区分业务缺口、permission_required、data_unavailable、system_error、明确外部失败、waiting_platform和unknown_outcome。
- 禁止空catch、默认成功、把失败变成空数组/0/正常状态，禁止直接持久化底层`error.message`。
- 只保存固定failureClass、安全错误码、脱敏evidenceRef和请求终态。
- Token、Cookie、密码、验证码、完整Key、Bearer、签名URL和原始私有响应不得进入业务对象、日志、UI、截图、测试fixture或提交。
- credentialAlias只是一条不含秘密的引用，不构成权限或业务授权。
- A公开采集、登录态读取、付费调用、ProductionAuthorization、E读取授权、unknown_outcome对账、部署授权相互独立，不能互相扩大。
