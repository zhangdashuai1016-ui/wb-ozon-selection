## 4. 最快、不绕弯的施工路线（推荐）

**原则：不改单 SKU 生命周期，不做多 SKU 大改；用「同款兄弟候选」复用整条已验通的单 SKU 流程，新代码只有四小块。**

1. **「追加同款颜色」动作**（新）：在已完成授权/导入的候选上，从 `sourceCapture.skuChoices` 中勾选未确认的规格（黑cp / CP / 黑色），每个规格生成一个兄弟候选：
   - `source` 新增 `sibling`（或复用 `software` 并带 `siblingOf`），字段 `siblingOf = 父候选 id`、`sharedSourceCaptureId`、`sharedDiscoveryEvidenceRef`、`sharedSalesSnapshotId`、`preselectedSupplierSkuId`；
   - 把父候选的 A 阶段证据（发现证据、销售快照、采集记录、供应商选项骨架）按只读引用带过去，并在兄弟候选上标明 provenance（AGENTS 2：共享引用不等于继承业务结论）；
   - 兄弟候选各自走：主人供货确认（预选该规格；价格/重量按主人「同重同价」声明）→ B（规格表）→ C1（**各自跑一次正式 C1 作业**，颜色事实替换，标题/描述由 AI 草稿按颜色重出；不要走带红灯的 C1 复用路径）→ C2（主人上传该颜色的图）→ 最终卡 → 授权（会自动起跑 D）→ 导入 → 观察 → 库存 → E。
2. **图片规则与 C2 校验**（新，确定性，按颜色分组而不是按变体）：
   - 每个颜色的 `main_image` 必须是该颜色自己的图；场景图、尺码图、功能图可以各色共用，但只能放在图库里，不能排第一。
   - 写入前：各颜色主图的本地文件 sha256 必须互不相同，且不得等于任何一张共用图的 sha256；不满足不许生成最终卡。
   - 写入后：Ozon 会转码改名，不能再比 sha256；E 只比 `primary_image` 的 URL——各颜色不同，且不等于 `images[]` 里任何一张共用图。
   - `color_image`（色样）建议逐颜色提供，不作硬门：没有时选择器显示文字，卡片照常可用（买家端渲染未实测，属推断）。色样会被裁成小圆图，用纯色或面料裁片比整只动物实拍更合适。
   - 新建商品时 `/v3/product/import` 每个 item 本身就带 `primary_image / images / color_image`，创建时按颜色填对即可，不要事后再用 `/v1/product/pictures/import` 补写（它是整组替换，漏掉的图会被删）。
3. **导入**：单 item 照旧；合卡条件是 **同 `description_category_id` + 同 `type_id` + 同品牌 + 同 `9048` 型号值**，各变体靠 `10096/10097`（颜色）与 `5952`（尺码）区分；`9048` 必须与父候选完全一致（同源货号，天然一致，但要断言）；`10096` 颜色走类目字典映射（黑色有字典值；黑cp / CP 若字典无则近似字典值 + `10097` 颜色名，按雨衣先例）；`color_image` 从固定空串改为可选字段：C2 有色样则发，没有则不发该字段（不发空串，见 r65 卡对空字符串的怀疑）。
4. **E 增一项**：用 `/v3/product/info/list` 的 `model_info.model_id` 与 `count` 核各兄弟是否与父候选同卡；合卡是异步的，创建后立刻回读可能滞后，按观察策略有限次数重查；`count` 会把已归档变体也算进去，比对时按未归档数。不一致只记差异不改写。
5. **评审台**：同款按父候选分组显示（父 + 兄弟一行，各自四条状态线），不合并成一张卡。
6. **本色图来源**：优先 1688 每个 SKU 的本色图（评审台记录里为 null，需从 1688 页面再采，走现有采集授权面），再由图片工作台按颜色出场景主图；主人在 C2 逐颜色上传并确认，第一张就是主图。
 7. **尺码表属性 13164 留空**（2026-09-24 销售分析会话发现）：雨衣手工脚本 `first-sku-listing/scripts/enrich2.mjs` 写的 `{"rows":[…]}` 格式虽被 `/v1/product/import` 接收，但卖家后台编辑器按 `table-constructor.ozon.ru/schema.json` 校验会标红，导致后台任何改动都无法「发送进行审核」。评审台生产适配器从未写过 13164，背心也未发过，追加颜色一轮继续不发；若将来某品需要尺码表，必须按该 schema 生成（`version` 为数字 0.1、`data` 全为字符串、宠物用品不用 `tcInstruction`）并先在沙盒验证，样例见 `/Users/shuaizhang/Documents/ozon/reports/preflight/miska-dog-raincoat-size-table-2026-09-24/size-table-13164.json`。

主人的点击（每个颜色）：供货确认 1 次、C2 上传并确认 1 次、最终卡通过进入生产授权 1 次（这一下会自动传图导入）；「同重同价」声明一次覆盖全部。共约 3×3 = 9 下加 1 次声明。

## 5. 验收终点

- 副本排练：从背心当前状态生成 3 个兄弟候选 → 逐个走到导入被接受（合成适配器）→ 观察 → 库存 → E；断言三个 item 的 `9048`、`description_category_id`、`type_id`、品牌相同，`10096` 各不同，主图 sha 各不同且不在共用集合里，`color_image` 有则发无则不发，库存请求各自仓库 1020005003808030 数量按各自授权。
- 反向：主图与父候选相同或等于共用图 → 最终卡被拒；`9048` 不一致 → 授权前拒绝。
- 真实首飞：黑cp / CP / 黑色三色上架并回读到与卡其色相同的 `model_id`；E 各自独立；`primary_image` 各不相同。
- 全量 CI 真实退出码；新文件登记归属与快照重生成；部署确认卡 r70（含主人点击顺序）。
