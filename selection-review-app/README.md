# 今日选品评审台

这是本地只读选品协作网页。它不会连接店铺写接口，也不会创建、发布或修改商品、库存、价格或广告。

## 使用

系统登录后会由 macOS 自动启动后台服务。重新打开浏览器时，直接打开
`今日选品评审台.webloc`，或双击 `启动今日选品评审台.command`。页面地址固定为：

`http://127.0.0.1:4317/`

后台服务只监听本机地址，不对局域网或互联网开放；异常退出后系统会自动拉起。
运行日志位于 `~/Library/Application Support/今日选品评审台/logs/`。

页面右上角“添加我找到的商品”只要求目标店铺和商品链接。保存后商品直接进入“Codex处理中”，不要求用户重复判断。

## 处理流程

评审台把选品拆成三段，禁止跨阶段混用淘汰理由：

1. **A 方向初筛**：检查目标平台市场、跨境商品份额（蛋蛋鼠主动研究门槛≥40%）、市场体量/趋势，以及市场价格减去可行物流后的初步正采购空间。此时不要求精确货源SKU；“具体款式/链接与目标款不一致”不能作为方向淘汰理由。明确IP/品牌风险也不自动淘汰，改为“需总控确认”。
2. **B 具体SKU利润核算**：用户提供目标SKU/款式、采购到手总价（含国内运费）、真实打包重量和尺寸后，直接读取目标平台市场、当前佣金及GUOO/CEL并算利润。供应商页能否打开不是前置条件。
3. **C 采购/上架前来源与合规核验**：核对精确货源链接与目标SKU是否一致，并检查权利/IP、合规、带电/电池及最终包装属性。若SKU不一致，只阻止该SKU采购/上架并继续找对的SKU，不得写成“方向淘汰”；IP/品牌风险未经总控/用户确认且未完成权利核验，不得进入待上架或写店。

- “待你确认”只放 Codex 选品。用户点“不行”后立即淘汰；点“可做”或“待确认”后自动进入 Codex 审核。
- “待你确认”每张候选卡都显示“含国内邮费采购价上限”。只有卖家收入、当前真实佣金和最终包装国际运费可追溯时才显示反算金额；证据不足时明确显示“采购上限未验证”和缺口，不生成猜测金额。
- “Codex处理中”不要求用户操作。用户提交的商品和已认可方向的商品都在这里自动核算市场、佣金、物流和利润。
- “需你补资料”只显示 Codex 无法自行取得的具体字段；保存后自动重新排队。
- 用户填写的“采购价”固定表示货价＋国内运费的到手总成本。系统不再拆分、重复询问国内运费；已经填写的采购价、重量、尺寸和精确链接也不得再次索取。若多规格页面与现有价格存在冲突，最多只确认一次该价格对应的目标SKU/套装。
- B阶段利润通过后仍须完成C阶段核验，完整门槛通过才进入“待上架”。上架任务完成真实回读后自动进入“已上架”；方向不成立或具体SKU利润不通过可淘汰，C阶段来源不一致只拦当前SKU采购/上架。六个队列互斥，同一商品只会出现在一个队列。
- 数据实时写入项目内的 `data/candidates.json` 共享入口，不是浏览器临时数据。
- 为避开 macOS 对“文稿”目录后台进程的隐私限制，该入口链接到
  `~/Library/Application Support/今日选品评审台/data/candidates.json`；Codex与网页读写的是同一份文件。
- 自动领取、定时重试和巡检目前暂停。候选处理只在总控明确指令后启动；不得用后台循环重试代替业务结论。
- 防空跑门禁：只有同时具备 `runId + startedAt + currentStep + lastProgressAt` 才显示“实际运行”；同一轮、同一证据层、同一目标只允许一次读取。一次有证据的技术失败立即停止并等待总控；15分钟没有新证据或真实步骤变化也会停止，只生成一条去重后的总控提醒，不再自动排队。
- 健康检查、队列未变化和重复证据不算业务进展，不得产生用户可见任务消息。
- 页面每3秒刷新共享数据；Codex写回后无需重新录入。
- 蛋蛋鼠主动研究按“Seerfar市场先行”执行：节日/趋势只是入口；跨境商品份额须≥40%，并先用目标Ozon市场价、当前佣金和可行包装物流建立正采购空间，再在正利润方向内找具体SKU。无正采购空间的方向不得进入用户待确认。
- Miska未来一周只审核用户主动提交品，不主动扩散或自动新增。至少积累5个完整、独立、利润通过并进入待上架的结构样本（同商品颜色/尺寸变体只算1个），且能归纳至少1个可检验共同经济结构后，才向总控提交1份共同点假设和最多3条Seerfar验证方向；未经确认不得新增。

## 严格门槛

只有同时满足以下条件，服务端才接受“审核通过”：

1. 非电，或带电商品已核实目标平台与实际物流线路均允许；
2. 合规与授权清楚；
3. 至少5个同规格市场证据，或用户明确接受测试风险；
4. 真实打包重量与尺寸完整；
5. 当前真实佣金、物流线路和完整利润复算通过；默认自然流量、广告成本为0，有真实投放计划时另算；
6. 蛋蛋鼠和 Miska 完整复算后，单件利润至少20 RMB或利润率至少15%，满足任一项即可。

20%/25%/30%是促销折扣空间，不是广告成本。若市场参照是折后成交价，利润直接从该成交价计算；建议标价分别按“折后成交价÷(1−促销率)”反推，禁止再从成交价扣一次促销率。若输入是标价，则先换算预期折后成交价再计算利润。已有候选的旧二次扣费结果保留为历史但不再作为当前结论，不自动重算、不静默覆盖。

“待上架”不等于“已经发布”；本工作台不执行任何店铺写操作。商品进入待上架前必须同时完成 WB 独立判断，页面只显示“WB也适合上架”或“WB不适合上架”，不保留“待计算”状态。只有完整复算 WB 当前类目、佣金、CEL物流、合规和利润满足20 RMB利润或15%利润率任一门槛，才能显示“WB也适合上架”。

## 上架任务自动回写

“待上架”的主流程不是用户手动点完成。上架任务在平台创建完成并重新读取当前状态后，调用：

`POST /api/candidates/{candidateId}/listing-readback`

请求必须包含当前 `dataRevision`，以及以下真实回读字段：

- `platform`：`ozon` 或 `wb`
- `store`：`dandanshu`、`miska` 或 `wb`
- `productId`、`merchantSku`
- `productUrl`（平台能够取得前台链接时填写）
- `confirmedAt`、`moderationStatus`、`saleStatus`
- `readback.sourceType="real"`
- `readback.source="seller_api"` 或 `seller_portal`
- `readback.checkedAt` 与 `readback.evidenceRef`

服务端只接受24小时内的 Seller API/卖家后台真实回读，并校验候选仍处于待上架、负责人为上架任务、平台与店铺一致、数据修订号没有过期。通过后自动保存完整上架记录、完成交接并移入“已上架”。重复发送同一平台商品回读是幂等的；不同商品不得覆盖。

页面中的“无法自动回读？手动标记”只是兜底。它会明确记录为 `manual_fallback`，不能伪装成自动回读，也不能依据旧聊天记录自动迁移。

“双方记录与留言”提供两种动作：“发送并交给Codex”会把非终态候选的问题标为待回复并重新送审；“仅记录”只保留历史，不触发重审。待上架和已上架商品由上架任务负责，不允许留言把同一SKU重新送回选品队列。Codex回复会关联原留言并显示“已回复”。
