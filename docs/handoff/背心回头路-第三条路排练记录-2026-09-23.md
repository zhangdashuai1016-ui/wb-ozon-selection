## 8. 按钮互斥规则（2026-09-23 讲解会话订正，已按真实代码核对）

判定函数确实存在：`lib/d-e-software-job-handoff.mjs:103` 的 `dProductionRoundDispatchable(document, candidate)`，返回 `{ dispatchable, blocker, supersededJobId, round }`。阻断原因枚举（按代码中的判定先后）：

`NO_ROUND` → `ROUND_NOT_STOPPED` → `ROUND_MAY_HAVE_SENT` → `DOWNSTREAM_EXISTS` → `REVISION_MOVED` → `ROUND_LIMIT`。

互斥规则（订正后，互斥对象是「再派一轮生产作业」而非「继续已保存任务」）：

| 状态 | 亮哪个 |
|---|---|
| `dispatchable === true` | 只亮「再派一轮生产作业」，隐藏「作废本轮授权」 |
| 被 `DOWNSTREAM_EXISTS` 或 `REVISION_MOVED` 挡住，且六项作废证据齐全 | 只亮「作废本轮授权」 |
| 其余（含 `ROUND_MAY_HAVE_SENT`、`ROUND_NOT_STOPPED`、`ROUND_LIMIT`、证据不齐） | 两个都不亮，分别显示各自的阻断原因 |

「继续已保存任务」照旧只在 `queued / attempt 0` 时亮，与上述两者无关。

**安全关键**：`ROUND_MAY_HAVE_SENT` 表示上一轮可能已经把请求发出去了（结果未知），此时**绝不能**亮「作废」——作废意味着当作没发生过，而请求终态未知时这个前提不成立。规则里把它排除在外是对的，用例必须覆盖。

**背心当前实测**（副本上运行判定函数）：

```
dispatchable = false
blocker      = DOWNSTREAM_EXISTS（本商品已经有素材传输、生产记录或回读结果，不能当作从未执行重派）
supersededJobId = d-production-job:ccba12a797…:round2
round        = 3
```

即背心命中的是 `DOWNSTREAM_EXISTS`（`dAssetTransport` 非空），落在「只亮作废」这一档。注意判定顺序上 `DOWNSTREAM_EXISTS` 先于 `REVISION_MOVED`，因此虽然候选 73 ≠ 授权 71 也成立，报出来的是前者。

**待定**：`ROUND_LIMIT`（轮次用尽，但无下游记录、修订也没动）目前两个按钮都不亮，是个死角。是否也该放行作废，留待决定，本轮不自行扩范围。
