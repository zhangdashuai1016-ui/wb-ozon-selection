## 2. 当前产品范围

第一阶段只优先打通一件全新试点商品的最小真实闭环：

`A → B → C1 → C2 → D → E`

- A：市场、方向、精确供货方案和主人供货确认。
- B：准确平台与店铺下，使用完整正式证据计算利润，并只创建一次C1交接。
- C1：商品事实、Schema、关键词、合规和SEO草稿。
- C2：素材三区、最终商品确认卡，以及主人作出生产决定后生成并持久化版本化ProductionAuthorization；生成授权仍不执行D。
- D：只消费已经持久化并通过当前身份、revision和范围校验的不可变ProductionAuthorization，执行一次受控平台写入。
- E：与D分开的独立回读、严格对账和结果分类。

一件商品跑通只证明第一条最小真实闭环，不代表批量、另一平台、另一店铺、多人中央运行或生产规模已经就绪。Ozon和WB都在产品范围内，但必须按平台、店铺、SKU、凭据、费用、作业、回执和E结果分别验证。

F店铺运营、G订单与客户、H财务经营、I复盘学习只确认了上层方向，内部规则继续后置。它们不是当前A到E的施工缺口、工位任务或验收前提，也不构成施工授权。

## 3. “薄总控”的职责

总控只做：

- 读取权威入口并标明本轮采用的老板意图版本、源码基线和证据时间。
- 把目标按真实依赖拆开，分配唯一负责人、文件所有权、输入输出合同和验收责任。
- 冻结跨阶段共享合同，处理边界冲突，监督依赖顺序和透明进度。
- 收集非作者复核、自动门禁、持久化回读和平台证据。
- 识别真正需要老板决定的问题，组织阶段签收和最终单商品闭环验收。

总控不做：

- 不亲自实现A、B、C1、C2、D、E领域代码，不替工位完成施工。
- 不代替领域工位判断业务规则，不把自己变成永久知识库或唯一裁判。
- 不与工位并发修改同一文件，不操作正常SKU，不访问平台，不执行部署。
- 不用聊天、旧测试数、页面显示、模块存在或任务回复宣布完成。
- 不给自己的实现签收；总控的最终结论必须来自独立证据。

## 4. 七个施工工位

总控不计入七个施工工位。

| 工位 | 唯一职责 | 主要输出 | 明确边界 |
|---|---|---|---|
| W1／A | 市场、销售证据、供货方案、精确供应SKU和主人确认 | 冻结且可追溯的A出口 | 不算正式B利润，不写店 |
| W2／B | 完整成本、正式费用证据、ProfitModel和唯一C1交接 | 正式B结果或明确缺口；一次C1 handoff | 估算或缺证据必须停B |
| W3／C1 | 事实、Schema、关键词、合规、SEO草稿和持久软件作业 | 可追溯C1计划与一次C2交接 | 不重访A/B，不改利润 |
| W4／C2 | 素材三区、finalUploads、最终商品确认卡；主人生产确认后生成并持久化版本化ProductionAuthorization | 主人可判断的最终卡；不可变生产授权 | 仅确认素材不等于生产授权；不执行D |
| W5／D | 只读并校验已持久化的不可变ProductionAuthorization，创建一次执行意图并调用平台写入适配器 | 真实回执、明确失败或unknown_outcome | 不生成或改写授权，不自证E，不得越授权字段 |
| W6／E | 店铺隔离的独立只读provider和严格比较 | EVerificationRecord或明确差异 | 不接受调用方自报冒充平台读取 |
| W7／共享与集成 | 共享入口、repository/事务、SoftwareJob、跨阶段Schema接缝、工作台投影和A到E集成测试 | 一条一致的共享运行接缝 | 不决定领域语义，不当监工或最终裁判 |

### C1到C2的媒体交接硬门

- 唯一设计关系是：`C1冻结事实输出 → C2素材需求／受控SoftwareJob → assets.aiDrafts → 主人确认的assets.finalUploads → 最终商品确认卡 → ProductionAuthorization → D`。作图、视频或其他模块不得越过C2直接生成授权、推进D或写平台。
- 图片是C2进入ProductionAuthorization和D的硬门：当前平台、店铺和类目所要求的图片槽位未满足，或主人尚未确认finalUploads、首图和顺序时，必须停在C2。
- 视频不是默认硬门。只有当前平台Schema或主人针对当前SKU明确要求时才阻塞C2；否则明确记录为`not_required`或“本次授权不含视频”，不得写成成功或unknown。
- 自动生成结果只能进入`assets.aiDrafts`。主人确认最终素材时必须新建并锁定可追溯的finalUploads清单，禁止把草稿原地改名成最终素材，也禁止把采集参考图自动提升。

### 文件所有权

- 同一时段一个文件只有一个写者；G1前冻结本轮精确文件清单和负责人。
- W1—W6只拥有本阶段领域模块和领域测试；不得直接修改共享入口来绕过合同。
- `server.mjs`、跨阶段Schema、repository/transaction、SoftwareJob、共享API、工作台入口/投影和跨阶段测试由W7串行收口。
- W7需要改变领域语义时，必须退回相关阶段和G1重新冻结，不能暗改合同或加兼容层拼接。
- 共享脏文件没有唯一负责人时，所有涉及该文件的施工停止。

### 验证和签收

- 工位作者：写计划、实现、自检并提交证据，但不能宣布自己通过。
- 下游工位：按输入合同复核上游交付是否可消费。
- W7：复核共享接缝和集成，不替领域作结论。
- 独立测试与安全审查：检查正常、边界、失败、权限、并发和回归路径。
- 总控：依据非作者证据签收阶段和跨阶段合同。
- 主人：决定真实产品语义、高风险动作、D精确授权和最终业务确认。

## 5. 精确任务授权和完成即停

每次派发必须写清：唯一目标、允许读取/修改的对象、输入、输出、负责人、禁止事项、验证方式、完成条件、失败停止点和交接对象。

- 只授权明确写出的动作。任务存在、工具可用、文件可见、当前线程活跃都不是授权。
- “不得做什么”只是限制范围，不会反向授权任何未明确允许的动作。
- 一个任务完成其唯一目标后立即停止；不顺手进入下一阶段、清理旧代码、部署、访问平台或扩大调查。
- 新要求若改变目标、公共合同、用户可见行为或副作用范围，必须重新派发，不能沿用旧授权。

## 6. 什么才需要问老板

只有问题会改变下列事项时，才交给老板：用户可见行为、业务语义、阶段职责、公共数据模型、正常主线取舍、破坏性迁移，或一次真实高风险动作的准确范围。

以下由工程证据决定，不得反抛给老板：文件和函数归属、普通实现方式、测试尚未运行、适配器技术比较、可由当前规则与同输入测试裁决的差异、已回答问题、明确后置问题，以及尚未到执行时点的运行对象授权。

当前唯一登记且不能静默裁决的跨文档业务歧义是`OPEN-MERGE-01`：带官方证据的受控人工E，是否仍可作为正式E支路。它不得被旧人工自报路线偷换，也不得阻塞独立provider这一软件正式路径的建设。

## 7. 综合优先级

发生竞争时，按“业务价值、真实风险、老板痛点、现有能力可复用程度、投入成本、闭环完整度”综合判断，不只看容易做、代码多或某一个数字。

执行顺序再受以下硬约束：

1. 安全和精确授权先于速度。
2. 当前事实、revision和证据先于聊天与旧结论。
3. 第一条A到E真实闭环先于UI美化、批量化和F到I扩展。
4. 先修会错误推进阶段、重复写入或污染业务真相的断点，再补便利功能。
5. 复用经过当前验收的能力；历史、模拟、重复和未知能力不得为省事回流主线。
6. 长期正确、唯一合同和可独立验收，优先于临时兼容和表面完成。

## 8. 高风险动作逐次精确授权

公开资料只读可以使用已经持久化、范围仍有效的SKU、批次或阶段授权；在授权范围内不逐页面重复询问，超出网站、动作、数量、对象、revision、阶段或排除项时必须零请求并重新取得授权。

下列高风险动作每一次都需要精确授权：登录态读取、付费调用、凭据或权限探测、素材外部上传、平台写入、D执行、unknown_outcome后的新轮次、部署或运行副本替换、服务重启、数据迁移/回填、删除/退役。任何授权都不得从公开只读授权、页面可见或工具可用中推导。

授权至少锁定适用动作、平台、稳定店铺/账号引用、candidate、SKU、merchantSku、revision/job、字段/素材/价格/库存、草稿或发布边界、次数/数量/费用、有效范围、排除项和默认禁止重试。秘密本体不得写入启动包、任务、日志或聊天。

低风险纠错可以在明确范围内形成可复用规则；风险高或风险未知的事项每次确认。只有主人明确选择“升级为长期规则”，才允许进入长期规则载体。

## 9. 全店能力地图的接线硬门

一个能力必须能独立说清“拿什么输入、做什么处理、交什么输出”，才可成为地图节点。面向主人的编号只使用稳定的纯数字分层编号；布局和拖动不得改号，退役编号不得复用。

任何能力进入正常关系图前必须依次通过：

1. **身份登记门**：稳定编号、职责、代码位置、身份类别和当前调用方明确；未登记项进入“待归位能力”。
2. **输入输出合同门**：输入、处理、输出、上游、下游、错误和停止条件明确，身份与revision可追溯。
3. **权限与副作用门**：本地保存、外部读取、付费、写店、凭据边界及所需主人授权明确。
4. **接线与验收门**：有真实调用关系、合同/集成/失败测试、非作者领域验收和当前证据；文件、按钮或测试文件存在不能代替接通。

未登记、疑似重复、实验、历史或用途不明能力只能隔离展示。AI可以提出候选接点，不能登记正式身份、选择重复实现、修改真实关系或宣布接通。

地图只读展示能力、关系、证据、风险和断点；它不是业务状态真相、派工器、部署台或接线控制台。拖动、展开和缩放只改变视觉位置，不改变依赖或业务状态。

## 10. 历史接管和透明披露

- 只有主人明确认可并保留、且能由当前文件或证据核实的成果，才能交接为“已确认成果”。
- 失败、回滚、被推翻或放弃的方案只作排除和风险证据，不能包装成已完成工作。
- 历史记录、旧测试数、旧候选、旧运行状态和旧授权只作线索；接手方必须重新读取当前事实。
- 历史读取被截断、不完整、找不到来源或受到权限阻塞时，立即明说读到哪里、缺什么、会影响什么；不能假装完成接管。
- 归档不等于删除，也不等于当前有效。恢复、迁移、合并或删除必须重新核查消费者并取得精确授权。

每次实质回报至少分别说明：读了什么、改了什么、没有改什么；运行了哪些验证；请求是否发出；是否发生付费、平台写入、运行副本或业务数据变化；结果是成功、明确失败、等待、阻塞还是unknown_outcome；error和warning是否存在。

## 11. 一个小块怎样才算完成

同时满足以下条件，才可提交总控签收：

1. 采用的现行规则和输入合同明确。
2. 真实实现存在，没有用假数据、宽泛兜底或第二套路径冒充。
3. 当前源码上的相关测试、语法/类型、构建和必要集成验证实际运行并通过，error和warning为零；环境限制单列。
4. 用户可见能力在工作台投影中真实可见；纯后台能力有可查询的状态和证据。
5. 非作者完成领域、测试和安全复核；下游明确接受交接。
6. 涉及真实业务时有持久化或平台独立回读；页面、API接受和脚本成功不够。

交互短规约：看不到就直说；主人说停就立即停；不要混淆对话、Skill、项目、业务状态和授权；用大白话先报结论、阻塞和最小下一步。
